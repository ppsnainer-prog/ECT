ЕЦТ Скрипты — исправленный комплект v2.7.18
=============================================

КЛЮЧЕВОЕ ИСПРАВЛЕНИЕ 404
-------------------------
Причина, найденная в исходниках: в проекте были ДВА разных fallback URL Apps Script.

1. app.js использовал:
   https://script.google.com/macros/s/AKfycbxpsNOmwaRLLMAql6XC_owTmDJO52EEskFbUCDCAhExaHLdvvijO17NRvc8kb4sBWopnA/exec

2. index.html использовал другой, старый deployment:
   AKfycbxk9hWog0sAruR4QRCM0t-oOFJTDvkHoA9mHy12ixT3dKWspy0Q2Pkiy85lJRnt_BlewA

Из-за этого login/index мог обращаться к одному deployment, а app.js — к другому.
Теперь URL находится только в config.js и используется всеми частями сайта.

ВАЖНО: если сам deployment Apps Script по текущему URL удалён/не опубликован, код сайта не сможет его восстановить.
В таком случае создайте новое Web App deployment и поменяйте URL ТОЛЬКО в config.js.

ПУБЛИКАЦИЯ САЙТА
----------------
Загрузите все 4 файла в одну папку репозитория:
  index.html
  app.js
  style.css
  config.js

Не удаляйте config.js.

ПУБЛИКАЦИЯ APPS SCRIPT
----------------------
1. Откройте Apps Script проект.
2. Замените содержимое Code.gs на Code.gs из этого комплекта.
3. Сохраните.
4. Развернуть → Управление развёртываниями.
5. Выберите Web app deployment.
6. Нажмите карандаш / Edit.
7. Выберите новую версию.
8. Выполнение: от вашего имени.
9. Кто имеет доступ: все, если сайт должен работать без Google-аккаунта.
10. Разверните.
11. Скопируйте URL вида:
    https://script.google.com/macros/s/XXXXXXXX/exec
12. Вставьте его в config.js:
    appsScriptUrl: '.../exec'
13. Обновите GitHub Pages.

ПРОВЕРКА APPS SCRIPT
--------------------
После публикации откройте:

  <URL_APPS_SCRIPT>/exec?op=health

Ожидаемый JSON содержит:
  "ok": true
  "service": "ECT Apps Script"
  "version": "2.7.18"

Если здесь HTTP 404 — проблема не в app.js, а в deployment Apps Script:
URL указывает на удалённое/неактивное развёртывание.

Если health работает, проверьте:
  <URL_APPS_SCRIPT>/exec?op=meta

Ожидается JSON с:
  ok
  op: "meta"
  updatedAt
  count
  guestLoginEnabled

ВАЖНО О БЕЗОПАСНОСТИ
--------------------
Текущая архитектура исторически делает Apps Script публичным Web App и принимает POST без серверной авторизации.
Это означает, что клиентская авторизация Александра/участников НЕ является полноценной серверной защитой:
пользователь, знающий endpoint, теоретически может отправлять POST напрямую.

Хэши в index.html убирают очевидную утечку plaintext-паролей из исходника, но не превращают
клиентскую авторизацию в серверную.

Если данные должны быть защищены от намеренного изменения извне, следующим этапом нужно перенести
авторизацию на сервер (например, серверная сессия/токен или отдельный backend). Просто добавлять
секрет в app.js нельзя — его также увидит любой посетитель сайта.

ПОВТОРНАЯ ПРОВЕРКА ПОСЛЕ ВЫКЛАДКИ
---------------------------------
1. Откройте /ECT/ в новой вкладке.
2. DevTools → Network.
3. Перезагрузите с Ctrl+Shift+R.
4. Убедитесь, что config.js, app.js и style.css имеют HTTP 200.
5. В Network найдите запрос:
   /exec?op=meta
   Он должен иметь HTTP 200.
6. Войдите под Александром.
7. Измените небольшой объект/скрипт и дождитесь статуса синхронизации.
8. Перезагрузите страницу.
9. Убедитесь, что изменение осталось.
10. Измените extras (например, цель/каталог) и снова перезагрузите.
11. Проверьте, что данные не пропали.
12. Проверьте гостевой вход.
13. Проверьте, что после отключения гостей кнопка гостя скрывается.
14. Проверьте длинный скрипт > 40 000 символов — должны использоваться chunks.
15. Повторите hard reload ещё 2 раза.

Если /exec?op=health отвечает 200, а сайт всё равно показывает 404,
проверьте Network: там должен быть указан точный URL запроса. Он должен совпадать
с config.js. Если виден старый deployment ID, очистите localStorage:
  localStorage.removeItem('ect_cloud_cfg_v1')
и перезагрузите страницу.

НЕ МЕНЯЙТЕ URL В app.js И index.html ВРУЧНУЮ
----------------------------------------------
После этой версии URL Apps Script меняется только в config.js.
Это предотвращает повторное появление рассинхрона.

Примечание
----------
В этой среде я могу полностью проверить загруженный архив и код статически, но не могу сам
опубликовать вашу Google Apps Script версию или GitHub Pages от вашего аккаунта.
Поэтому финальная проверка HTTP 200/404 должна быть выполнена после публикации deployment.
